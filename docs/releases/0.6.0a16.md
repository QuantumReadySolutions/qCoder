# qCoder 0.6.0a16

qCoder 0.6.0a16 is a behavior-changing pre-release successor to qCoder 0.6.0a13. It is not a
stable or generally available release, and package publication does not activate a named-client
support claim.

This release preserves the a15 IDE-first source-only authority model while reducing mandatory
connected-assistant context. The inline binding contains the operational core; specialized
contracts are digest-addressed and fail closed if a required reference is unavailable or does not
match. Normal successful coordinator results carry one compact procedural source instead of
repeating semantics, invocation, and customer-envelope projections.

After one action-specific native source write, the assistant immediately performs the exact bound
completion and registration in the same assistant turn. The two mandatory qCoder control cycles
remain separate, exact-path registration remains receipt-bound and single-use, and a failed write
cannot be registered. Source-only work still grants no QASM, execution, results, Evidence Review,
or governing-change authority. Exactly twelve public Context Bridge tools remain available.

Known limitation in qCoder 0.6.0a16: After source or circuit evidence is replaced within an active Current Loop, Run Summary may combine the new upstream artifact with older downstream circuit or result evidence and present the mixed-revision set as current. Bare count-like JSON may also be accepted without established circuit lineage. Individual artifacts may still be valid evidence in isolation, but do not use a16 Run Summary to conclude that the latest source, circuit, and result belong to one coherent execution.

Publication state, deployment state, and qualification claims remain separate from these immutable
package bytes.
